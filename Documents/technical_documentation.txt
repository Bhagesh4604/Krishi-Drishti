1. OVERVIEW
================================================================================

Krishi-Drishti (meaning "Farm Vision" in Sanskrit) is a full-stack, AI-driven
agricultural platform built for Indian farmers. It combines satellite remote
sensing, machine learning, GenAI, and blockchain-inspired carbon credit mechanics
to help farmers:
  - Monitor crop health using satellite imagery (NDVI, EVI, soil moisture)
  - Detect pests and diseases using computer vision and bioacoustics
  - Earn carbon credits (ACT tokens) through verified sustainable farming
  - Access market prices, government schemes, insurance, and digital contracts
  - Chat with an AI farming assistant in their local language

The system has two components:
  1. Farmer Web App     — React/TypeScript SPA (runs on localhost:3000)
  2. FastAPI Backend    — Python REST API + ML models (runs on localhost:8000)
  3. Admin Dashboard    — Standalone HTML/JS dashboard (no build step required)
  4. Bioacoustic Service — Separate Flask/TensorFlow microservice

6. AUTHENTICATION & SESSION MANAGEMENT
================================================================================

Mechanism: OTP-based Phone Authentication (no password)

Flow:
  1. User enters phone number → POST /api/auth/send-otp
  2. Backend generates 4-digit OTP (hardcoded "1234" for demo, master: "0000")
  3. In production: Twilio/Msg91 SMS API would send the OTP
  4. User enters OTP → POST /api/auth/verify-otp
  5. Backend verifies OTP from in-memory store (otp_store dict)
  6. On success: Creates user in DB if not exists, issues JWT token
  7. JWT token stored in localStorage as 'ks_token'
  8. All protected endpoints use: Authorization: Bearer <token>

JWT Details:
  - Algorithm: HS256
  - Payload: {"sub": "<phone_number>", "exp": <timestamp>}
  - Expiry: Configurable via ACCESS_TOKEN_EXPIRE_MINUTES
  - Library: python-jose

Security Notes:
  - Token validated on every protected endpoint via get_current_user dependency
  - 401 Unauthorized returned on invalid/expired tokens
  - Frontend clears localStorage on 401 response (auto-logout)

─────────────────────────────────────────────────────────────────────────────
7.1  NDVI & VEGETATION INDEX CALCULATION
─────────────────────────────────────────────────────────────────────────────

NDVI = (NIR - RED) / (NIR + RED)
  Where:
    NIR = Near-Infrared reflectance (Sentinel-2 Band 8)
    RED = Red reflectance (Sentinel-2 Band 4)

  NDVI Values:
    < 0.2  → Bare soil / very low vegetation
    0.2–0.5 → Moderate vegetation / stressed crop
    > 0.5  → Healthy dense vegetation

EVI (Enhanced Vegetation Index):
  EVI = 2.5 * (NIR - RED) / (NIR + 6*RED - 7.5*BLUE + 1)
  - Less sensitive to atmospheric noise than NDVI
  - Used for soil moisture correlation

MSAVI (Modified Soil-Adjusted Vegetation Index):
  MSAVI = (2*NIR + 1 - sqrt((2*NIR+1)^2 - 8*(NIR-RED))) / 2
  - Corrects for bare soil reflectance effects

Location: backend/services/earth_engine.py
          backend/services/agromonitoring.py


─────────────────────────────────────────────────────────────────────────────
7.2  CARBON CREDIT (ACT) CALCULATION ALGORITHM
─────────────────────────────────────────────────────────────────────────────

Step 1 — Baseline SOC Estimation:
  baseline_soc = district_default_soc    # tonnes C/ha (from ICAR data)
  baseline_emission = baseline_soc * area_ha

Step 2 — NDVI Growth Analysis:
  ndvi_change = current_ndvi - baseline_ndvi
  incremental_soc = ndvi_change * methodology_factor * area_ha
    Where methodology_factor:
      Cover-Crop:   1.2 tCO2e/ha/year
      No-Till:      0.9 tCO2e/ha/year
      Agroforestry: 2.1 tCO2e/ha/year

Step 3 — Gross Credits:
  gross_credits = incremental_soc * 5      # 5-year vesting period

Step 4 — Buffer Pool Deduction (Insurance):
  buffer_pool = gross_credits * 15%        # CCTS standard: 10-20%
  locked_credits = buffer_pool
  issuable_credits = gross_credits - buffer_pool

Step 5 — Additionality Check (ICAR/NABARD Data):
  If practice_adoption_rate_in_district > 50%:
    → REJECTED (not additional, common practice)
  Else:
    → ELIGIBLE for credits

Step 6 — Credit Value:
  credit_value_inr = available_credits * ₹1,200 per ACT
  aggregator_fee = credit_value_inr * 20%
  farmer_payout = credit_value_inr * 80%

Location: backend/routers/carbon.py
          backend/services/additionality_service.py
          backend/ml_models/soc_estimator.py


─────────────────────────────────────────────────────────────────────────────
7.3  CROP YIELD PREDICTION — ML MODEL
─────────────────────────────────────────────────────────────────────────────

Algorithm: Random Forest Regressor (scikit-learn)

Features used:
  - NDVI health score (0.0 to 1.0)
  - Soil moisture (%)
  - Crop type (encoded categorically)
  - Organic score (0 to 100)

Training:
  - Synthetic training data generated using agronomic constants
    from ICAR crop yield tables (Wheat: 3.5 t/ha, Rice: 4.2 t/ha, etc.)
  - 500 synthetic samples with realistic noise injection
  - Train/test split: 80/20
  - Model saved in-memory (no .pkl file — retrained on startup if needed)

Prediction formula:
  base_yield = crop_constant (from ICAR tables)
  ndvi_factor = health_score * 2.0     (range: 0-2x multiplier)
  moisture_factor = moisture / 35.0    (optimal at 35%)
  predicted_yield = base_yield * ndvi_factor * moisture_factor

Location: backend/ml_models/yield_predictor.py


─────────────────────────────────────────────────────────────────────────────
7.4  ANOMALY DETECTION — NDVI TIMESERIES
─────────────────────────────────────────────────────────────────────────────

Algorithm: Z-Score based statistical anomaly detection

Logic:
  1. Collect historical NDVI values for a plot (last 6 months)
  2. Calculate mean and standard deviation
  3. Z-score = (current_value - mean) / std_dev
  4. If |Z-score| > threshold (1.5): mark as anomaly = True
  5. Minimum data required: 5 data points

  Special case:
  - If std_dev is very small (< 0.001): use 2% relative threshold
    (handles cases where NDVI is very stable — sudden change flagged)

Use: Admin dashboard plots and farmer crop stress screen show anomaly flags.
     Red marker on NDVI graph = anomalous reading = potential problem.

Location: backend/ml_models/anomaly_detector.py


─────────────────────────────────────────────────────────────────────────────
7.5  DISEASE RISK FORECASTING — ML MODEL
─────────────────────────────────────────────────────────────────────────────

Algorithm: Rule-based expert system + Random Forest Classifier

Disease factors evaluated:
  - Temperature range (monthly average from weather data)
  - Humidity percentage
  - NDVI stress level (NDVI < 0.5 = stressed crop)
  - Soil moisture (overwatered crops are disease-prone)
  - Crop type (different diseases per crop)
  - Season (Kharif vs Rabi season detection)

Risk Levels: High / Medium / Low

Diseases covered:
  Wheat:  Rust, Powdery Mildew, Blast
  Rice:   Blast, Brown Plant Hopper, Sheath Blight
  Cotton: Boll Weevil, Leaf Curl Virus, Fusarium Wilt
  Tomato: Late Blight, Bacterial Wilt, Leaf Miner
  Potato: Early Blight, Late Blight, Black Scurf

Recommendation generation: Uses Gemini AI to generate crop-specific,
  context-aware organic treatment advice.

Location: backend/ml_models/disease_forecaster.py


─────────────────────────────────────────────────────────────────────────────
7.6  BIOACOUSTIC PEST DETECTION — DEEP LEARNING
─────────────────────────────────────────────────────────────────────────────

Model: Convolutional Neural Network (CNN) on Mel Spectrograms

Pipeline:
  1. Input: Audio file (WAV/MP3) uploaded by farmer
  2. Feature extraction (librosa):
     - Load audio at 22050 Hz sample rate
     - Generate Mel Spectrogram: n_mels=128, hop_length=512
     - Convert to log scale (dB)
     - Resize to (128, 128) fixed input size
  3. CNN Architecture:
     - Conv2D(32, 3x3, ReLU) → MaxPool2D(2x2)
     - Conv2D(64, 3x3, ReLU) → MaxPool2D(2x2)
     - Flatten → Dense(128, ReLU) → Dropout(0.5)
     - Output: Dense(num_classes, Softmax)
  4. Output: Pest class + confidence probability

Pest Classes:
  - Aphids, Whiteflies, Thrips, Mealybugs, Spider Mites,
    Leaf Miners, Fruit Flies, Crickets, Grasshoppers, No Pest

Training:
  - Synthetic audio generation using librosa tone synthesis
  - Each pest class gets characteristic frequency range
  - 50 samples per class, 10 classes total
  - 10 epochs, Adam optimizer, categorical crossentropy loss

Location: backend/bioacoustic_service/server.py
          backend/bioacoustic_service/model_trainer.py


─────────────────────────────────────────────────────────────────────────────
7.7  SOC (SOIL ORGANIC CARBON) ESTIMATION
─────────────────────────────────────────────────────────────────────────────

Model: Multi-variable linear regression with NDVI correlation

Input: Lat/Lng coordinate from farmer field marking

Algorithm:
  1. Look up soil type zone from coordinate (climate-zone lookup table)
  2. Apply base SOC from district crop calendar data
  3. Adjust for:
     - NDVI (higher vegetation = higher organic matter)
     - Soil moisture (wetter = more microbial activity)
     - Farming practice (organic farming = +20-40% SOC)
     - Slope / elevation (estimated from lat/lng band)
  4. Output: SOC value in g/kg (grams per kilogram of dry soil)

Calibration: Uses ICAR SOC baseline maps for Maharashtra/UP/MP districts.

Lab validation: Farmer can manually enter their actual lab SOC reading
  to "ground-truth" the satellite estimate (Enter Lab SOC field).
  The ground-truth data improves future predictions.

Location: backend/ml_models/soc_estimator.py
          backend/ml_models/soc_model.py
          screens/SoilCarbonModelScreen.tsx

7.9  RAG (RETRIEVAL AUGMENTED GENERATION) FARMING ASSISTANT
─────────────────────────────────────────────────────────────────────────────

The AI chat assistant uses RAG to answer farming questions with
  government scheme data and crop-specific knowledge.

Pipeline:
  1. Document ingestion (backend/services/rag_indexer.py):
     - PDF/Text farming documents loaded
     - Split into chunks (512 tokens each)
     - TF-IDF vectors stored in memory index
  2. User query comes in → POST /api/ai/chat
  3. Hybrid search (backend/services/hybrid_search.py):
     - Keyword search on chunks (BM25-style)
     - Semantic similarity using cosine distance
     - Top-3 relevant chunks retrieved
  4. Augmented prompt sent to Gemini:
     "Context: [retrieved chunks]\nQuestion: [user_query]\nAnswer in [language]:"
  5. Gemini generates contextual answer
  6. Language: Supports English, Hindi, Marathi (set via language toggle)

7.10  DETERMINISTIC PSEUDO-RANDOMNESS (SATELLITE SIMULATION)
─────────────────────────────────────────────────────────────────────────────

For development/demo when live satellite data is unavailable,
  the system uses deterministic hash-based simulation:

def det_float(seed_str, min_v, max_v):
  hash_val = int(md5(seed_str.encode()).hexdigest()[:8], 16)
  return min_v + (hash_val / 0xFFFFFFFF) * (max_v - min_v)

The seed is always unique per plot (name + user_id + methodology),
  so every plot gets stable, consistent "simulated" NDVI readings
  that don't change on each page refresh — making it feel like real
  satellite data.

Location: backend/routers/plots.py, backend/routers/carbon.py


─────────────────────────────────────────────────────────────────────────────
7.11  GPS POLYGON AREA CALCULATION (LAND MARKING)
─────────────────────────────────────────────────────────────────────────────

Algorithm: Spherical Excess Formula (geodetic polygon area)

function calculateArea(coords):
  for each edge (p1, p2):
    area += (lng2 - lng1) * (2 + sin(lat1) + sin(lat2))
  area = |area| * R^2 / 2
  where R = 6,378,137 metres (Earth's radius)

Output: Area in square metres → converted to hectares and acres
  1 hectare = 10,000 m²
  1 acre = 0.000247105 m²

Modes:
  - TAP MODE: User taps corners on satellite map
  - WALK MODE: GPS watch-position records path as farmer walks boundary
  - SURVEY MODE: Enter survey number to auto-fetch boundary (demo)

Location: screens/LandMarkingScreen.tsx

10. CARBON CREDIT METHODOLOGY (INDUSTRY STANDARDS)
================================================================================

Framework: CCTS (Carbon Credit Trading Scheme) — Bureau of Energy Efficiency
Secondary: VCS (Verified Carbon Standard) — Verra International
           GCP (Green Credit Program) — MoEFCC India

MRV = Monitoring, Reporting, Verification (the 3 pillars)

MONITORING:
  - Sentinel-2 satellite imagery (10m resolution, free via Copernicus)
  - NDVI timeseries monitoring (every 5-10 days)
  - Soil moisture from Sentinel-1 SAR data

REPORTING:
  - Farmer uploads geo-tagged field photos (evidence)
  - GPS coordinates logged for each photo (immutable)
  - Audit log of all farmer operations (immutable DB table)

VERIFICATION:
  - Additionality check: Is this farming practice "new" in the district?
    (Data source: ICAR/NABARD district cultivation surveys)
  - Evidence check: ≥ 1 photo for rainfed, ≥ 2 for soil-based methods
  - Satellite cross-check: NDVI must show measurable positive change
  - Buffer pool: 15% of credits locked for 5 years as insurance

ACT TOKEN (Agri Carbon Token):
  1 ACT = 1 tonne of CO2 equivalent sequestered in farmland
  Price: ~₹1,200 per ACT (Indian voluntary carbon market rate, 2024-25)
  Farmer share: 80%     (after 20% aggregator fee)
  Vesting period: 5 years (credits released gradually)

13. KNOWN LIMITATIONS & FUTURE ROADMAP
================================================================================

Current Limitations:
  1. Database: SQLite (single-file, not suitable for production at scale)
     → Migrate to PostgreSQL for multi-user production
  2. OTP: Hardcoded / in-memory (resets on backend restart)
     → Integrate Twilio or Msg91 for real SMS OTP
  3. Satellite: Simulated NDVI (deterministic hash-based)
     → Integrate real Google Earth Engine or Sentinel Hub API
  4. JWT tokens stored in localStorage
     → Move to HttpOnly cookies for production security
  5. Bioacoustic model trained on synthetic audio
